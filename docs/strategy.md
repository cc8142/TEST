# 测试策略与计划

## 背景与目标
- 业务背景：多端电商与金融风控，交易路径复杂、时效要求高
- 质量目标：核心链路零阻塞、回归可在 4 小时内完成
- 主要风险：支付与风控规则变更、跨服务依赖、灰度发布回滚

## 测试范围与优先级
- 核心流程：登录、搜索、下单、支付、退款、风控判定
- 非核心流程：营销配置、报表导出、低频运营工具
- 不在范围内：第三方支付网关与外部数据源的可用性

## 测试金字塔策略
- 单元测试：由研发负责，确保核心业务逻辑覆盖
- 接口测试：主战场，覆盖交易与风控核心 API
- UI 测试：只覆盖关键路径与跨端一致性
- 比例建议：单元 60%，接口 30%，UI 10%

## 风险驱动与测试设计
- 高风险清单：订单状态流转、优惠叠加、风控命中与拒绝
- 关键路径用例：新客首单、活动叠加、退款逆向流程
- 失败场景：超时重试、并发冲突、幂等校验、异常回滚

## 回归策略
- 日常回归：PR 触发、接口集为主，确保核心 API 30 分钟内完成
- 发版回归：夜间全量回归，UI 仅覆盖关键链路
- 分层回归：接口覆盖全量，UI 分阶段执行

## 套件划分与触发
- smoke：PR/提交门禁，10 分钟内完成
- api：夜间全量/版本前回归
- ui：契约 + 真浏览器两层
- e2e：发布前端到端验证

## 标记与选取
- pytest markers：api/ui/smoke/e2e
- 运行入口：`python tests/run_all.py --suite api`

## 进入/退出标准
- 进入标准：环境稳定、需求冻结、测试数据准备完成
- 退出标准：核心链路 100% 通过、阻塞缺陷清零、回归稳定性 98%+

## 风险与应对
- 风险：依赖服务波动、测试数据污染、回归窗口不足
- 应对：Mock 关键依赖、数据隔离与回收、分层回归与并行执行
